# 故事改写（Story Rewriter）

一个可通过 Git URL 安装的 SillyTavern 前端扩展。用户只需要指出问题位置并描述修改目标，插件会结合酒馆完整上下文生成一个保留原版本的新版本。

> 当前版本：`0.6.0`。建议先在非关键聊天中试用，并为重要聊天保留备份。模型、预设与世界书兼容设计参见 [v0.6 通用性重构](docs/V0.6_PORTABILITY_REFACTOR.md)。

## 功能

- 在 AI 消息中选中文字后显示统一的“修改”入口。
- 在消息工具栏直接启动“修改这条回复”。
- 输入自然语言修改要求，例如“事件不变，语气更克制”。
- 使用 SillyTavern 当前启用的模型和 API，不需要单独配置第二个模型。
- 默认通过 SillyTavern 原生后台生成流程使用当前角色卡、激活的世界书、作者注、扩展提示和聊天历史。
- 支持“智能关联调整”和“仅改选区”两种用户可理解的修改范围。
- 会为原文建立稳定段落编号，先分析影响范围，再生成完整候选稿。
- 酒馆完整上下文是角色、预设和世界书的唯一事实来源；插件不会二次注入未激活世界书。
- 从聊天历史建立只读虚拟资料库，并按本轮目标召回可能已离开当前上下文窗口的相关剧情。
- 展示本次实际使用的资料来源和因预算省略的匹配数量。
- 本地比较原文与候选，把变化分为强修改、关联修改、衔接调整和疑似越界。
- 支持逐块决定是否采用修改；计划内变化默认采用，疑似越界默认保留原文。
- 支持“仅采用计划内”“全部采用”“全部保留原文”，即时合成完整版本且不重复调用模型。
- 明显截断、大范围无关重写和保护事实冲突会显示高风险确认；审计不会剥夺用户最终保存或覆盖的权力。
- 所有主要修改默认应用为新的 Swipe，原回复保持不变。
- 右侧编辑工作台不会遮住聊天，可围绕同一选区连续提出多轮要求。
- 长文本工作台可拖动左缘调整宽度，完整版本使用单栏大编辑区。
- 完整正文使用纯文本结束标记；触及单次响应上限时会自动分段续接并去除重叠，不再因长正文 JSON 被截断而整篇报废。
- 完整正文由插件识别并清理显式推理块，避免酒馆的全局推理格式误把整篇正文删除；空正文会自动强化要求重试一次。
- 智能关联模式会验证候选是否足以覆盖保护区；模型把局部片段冒充全文时自动重新请求完整消息。
- 段落差异使用顺序与相似度联合对齐，插入或删除段落后仍让展示、复选框和最终合成落在同一原文位置。
- 单换行、常见紧凑 HTML 和长篇无空行正文会自动形成可审阅结构块，合成时保留原始分隔格式。
- 影响分析优先使用 JSON Schema；后端不支持时自动切换无 Schema 标记协议，再失败则使用本地保守范围。
- 模型置信度只作为界面参考，不会剥夺任何段落的用户选择权。
- 缩短、保持或扩写由影响计划中的统一长度意图控制，不依赖中英文关键词表。
- 可以填写需要持续遵守的约束，恢复本次会话的旧候选。
- 候选可手动修订，并会在保存前重新审计。
- 只改动所选片段，保留消息其余内容。
- 默认通过 SillyTavern 原生 Swipe 返回旧版本；旧版覆盖式修改的撤销记录仍保持兼容。
- 兼容常见 Markdown 选区，包括强调、链接、实体字符和换行。
- 长距离拖选或滚动页面时，工具条会在滚动停止和指针释放后重新定位到当前可见选区。

## 安装

1. 打开 SillyTavern 的“扩展”面板。
2. 选择“安装扩展”。
3. 输入仓库地址：`https://github.com/zhanglongyi99/sillytavern-custom-plugin`
4. 完成安装后刷新 SillyTavern。

需要 SillyTavern 1.17.0 或更高版本。该项目是纯前端扩展，不需要服务器插件、构建步骤或额外依赖。

## 使用

### 修改选中内容

1. 在一条 AI 回复内圈选需要修改的文字。
2. 点击选区附近的“修改”。
3. 输入修改要求，并选择“智能关联调整”或“仅改选区”。
4. 在“逐块确认”中勾选要采用的变化，并在“新版本”中检查合成后的全文。
5. 点击“应用为新版本”。原回复仍可通过 SillyTavern 原生 Swipe 返回。

### 修改这条回复

点击 AI 消息工具栏的“修改这条回复”，不需要先选择文字。输入“重新梳理贞德线，玛修设定保持不变”等要求，Agent 会自动识别相关段落，不会因为没有选区而平均重写全文。

### 逐块确认

模型生成后默认进入“逐块确认”。每个差异块都可以独立选择“采用此修改”；疑似越界块默认关闭。切换复选框或批量操作只会在浏览器本地重组候选，不会再次调用模型。直接编辑“新版本”后，插件会把手工文本重新拆成差异块，并默认保留这些人工修改。

### 上下文

插件默认通过酒馆完整上下文生成，自动沿用当前角色卡、实际激活的世界书、作者注、扩展提示和聊天历史。插件只按需补充相关旧聊天证据，不会再次扫描和发送整本世界书。只有完整接口不可用时才自动降级到本地上下文快照；该快照通过酒馆自己的世界书激活接口取得当前有效内容。

Token 预算会同步 SillyTavern 当前 API/Chat Completion 预设真正生效的上下文与响应上限（包括 100 万上下文预设），并调用酒馆当前模型的 tokenizer 计数。工作台会显示实际读取到的预设上限；若只能使用旧接口兜底，则明确显示为“兼容上限”。

影响分析只返回紧凑的段落索引计划，不复制大段原文。旧版 1400 Token 的默认分析预算会自动迁移到 4096；工作台同时显示当前响应上限，便于区分“上下文不足”和“模型输出被截断”。

完整候选的默认总预算为 32768 Token，旧版不高于 8192 的默认值会自动迁移。该值是最多 8 个自动续接段的合计预算；每一段仍遵循当前酒馆预设的单次响应上限。如果总预算耗尽后仍没有收到结束标记，插件会保留已有候选并给出高风险提示，最终是否编辑或应用仍由用户决定。

## 设置

- `启用选区改写`：临时关闭或开启选区按钮。
- 普通设置只保留启用开关。
- 高级设置可调整输出长度、资料预算、分析预算和旧版配置兼容项。
- 版本回退优先使用 SillyTavern 原生 Swipe；旧的局部撤销记录仍可按需保留。

## 当前限制

- 仅支持普通 AI 消息，不处理用户消息、系统消息或跨消息选区。
- 选区修改当前只支持一个连续选区；多选区和画笔式标记尚未实现。
- 如果消息使用了与原始文本不同的 `display_text`，为避免定位错误不会显示改写按钮。
- 选区映射覆盖常见 Markdown，但复杂 HTML、插件自定义渲染或非常规 Markdown 可能无法定位。
- 替换历史消息不会自动重新生成它后面的故事内容；后续消息可能需要手动调整。
- 完整模式修改历史消息时会参考目标消息之后的现有剧情，以尽量避免冲突；暂不支持“只看到目标消息及其之前内容”的时间线截断模式。
- 世界书严格遵循酒馆自己的激活和 Token 预算。完整模式不单独列举每条世界书来源，因为它们已经属于酒馆最终提示链；本地降级模式只使用酒馆激活后的世界书快照。
- 本地历史检索使用 Unicode 词元、字符片段、来源权威性和剧情新旧的混合评分，不使用语义向量，仍可能漏掉完全没有共享文本线索的隐含联系。
- 影响计划和保护事实仍由模型参与判断；插件会验证段落、引文和来源 ID，但基础事实审计不能保证识别所有语义冲突。
- 智能关联调整通常调用模型两次，耗时与消耗高于仅改选区，并可能触发其他扩展注册的生成钩子。
- Diff 使用顺序感知的段落动态对齐；大幅调换段落顺序时仍可能把移动显示成删除和新增。
- 逐块合成支持空行、单换行、常见 HTML 块和长篇句群；自定义渲染与极端段落调序仍可能需要在完整预览中手工整理。
- 模型仍可能返回超出要求的内容，请在应用新版本前检查预览。
- 影响分析和仅改选区优先使用结构化 JSON，但会按运行时响应能力自动降级；完整候选正文使用纯文本结束标记与自动续接。推理内容优先通过酒馆当前推理模板解析，常见标签仅作为最后兜底。

## 开发与检查

需要 Node.js 18 或更高版本：

```bash
npm run check
npm test
```

项目不需要安装 npm 依赖。核心结构：

```text
manifest.json       SillyTavern 扩展清单
index.js            扩展生命周期、界面和消息写回
settings.html       扩展设置面板
style.css           界面样式
lib/selection.js    可见选区到原始 Markdown 的定位
lib/rewrite.js      模型提示词和结果处理
lib/semantic.js     段落、资料检索、影响计划、完整候选和审计
lib/swipe.js        安全追加完整候选 Swipe
tests/              无浏览器依赖的单元测试
```

实际酒馆界面的回归步骤参见 [v0.4 手工验证清单](docs/V0.4_MANUAL_TEST.md)。

# 故事改写（Story Rewriter）

故事改写是 SillyTavern 前端扩展。它可以帮你改写一条 AI 回复中的指定内容、检查整条回复是否存在前后矛盾，并把结果作为新 Swipe 保存，方便比较或切回原文。

## 安装

0.8.4：审阅优先核对同一事件、时间地点、物品流转和人物知情的跨段一致性。连续性问题需双侧原文依据与替代解释核对；统一依据不明时保留待确认，不自动改写。报告展示双侧引文；程序只验证引文存在，不保证模型语义判断正确。不新增默认调用。

0.8.3：检查报告优先解析有效数据，再尝试配置清理；区分空返回、清理后为空和不完整报告。新增分阶段长度诊断，不记录报告正文，不增加重试次数。

0.8.2：整章检查保留完整本章，历史资料统一限额；自动修订仅带入已确认问题的引用依据。修订后提供逐项目标变化提示，计划外变化仍默认保留原文。“长度比”和“目标已变化”均不代表语义问题已解决，请确认后应用。不增加默认模型调用次数。

1. 在 SillyTavern 打开「扩展」面板，选择安装扩展。
2. 输入仓库地址：`https://github.com/zhanglongyi99/sillytavern-custom-plugin`
3. 安装后刷新 SillyTavern 页面。

需要 SillyTavern 1.17.0 或更高版本。扩展使用酒馆当前选择的模型和 API，无须单独配置模型。

## 快速开始：修改一条回复

### 修改整条回复

1. 点击 AI 回复工具栏中的「修改这条回复」。
2. 在「本轮修改要求」中描述目标，例如：「重新梳理贞德线的发展，玛修的设定和其他剧情保持不变」。
3. 点击「生成新版本」。扩展会分析修改范围，生成一份完整候选稿。
4. 查看「逐块确认」和「新版本」全文。选择要保留原文或采用新版的变化。
5. 确认无误后点击「应用为新版本」。原版本会保留在 SillyTavern 的 Swipe 中。

如果需要连续调整，直接在工作台继续输入要求并生成。选择「继续当前版本」会接着修改当前合成稿；选择「从原文开始新任务」会重新以原回复为基础。

### 只修改选中的内容

1. 在 AI 回复中选中一段文字，点击附近出现的「修改」。
2. 描述你希望如何改写。
3. 选择修改范围：
   - **智能关联调整**：可以同时调整与选区有关的因果、伏笔和衔接，适合改剧情或人物关系。
   - **仅改选区**：只生成选区的替换文本，圈外内容保持原样，适合局部措辞或细节修改。
4. 检查候选并应用。应用后原回复仍可从 Swipe 切回。

## 检查整条回复

在工作台展开「检查要求与选项」，可以填写希望长期遵守的检查要求，例如时间线、人物称呼或格式规则。该要求保存在本机浏览器中，之后打开工作台仍可编辑。

点击「检查这条回复」后，默认行为是：

1. AI 通读并检查整条回复，列出有依据的问题。
2. 如果找到明确问题，自动生成一份修订候选；没有明确问题时只显示检查结果。
3. 如果缺少关键历史证据，扩展会按检查目标查询聊天记录，并将找到的资料交给 AI 复核一次。
4. 查看问题、引用依据和修订候选，逐块确认后再应用。

取消「有明确问题时生成修订候选」后，功能只检查，不生成修订稿。检查会使用酒馆当前上下文、前序聊天和相关资料；未检索到的历史不保证覆盖。资料不足时，报告会将问题标为「待确认」，不会自动据此修改。

## 如何看逐块对照

- 每张卡片显示原文、候选和变化类别。点击「保留原文」或「采用新版」决定该块最终使用哪一版。
- 「高亮变化」开启时，原文中被删改的部分以红色标出，候选新增的部分以绿色标出。
- 可在「上下对照」和「左右对照」之间切换，也可筛选计划内变化或疑似越界变化。
- 「仅采用计划内」「全部采用」「全部保留原文」会在本地合成版本，不会再次调用模型。
- 「新版本」页展示最终合成的全文，也可以手动编辑；应用前请检查全文。

## 上下文与资料

默认使用 SillyTavern 当前的完整生成上下文，包括当前角色卡、实际激活的世界书、作者注、扩展提示和聊天历史。扩展也会从历史中检索与本轮目标相关的片段，并在「使用的资料」中展示本次检索结果。

扩展不会自行启用或重复注入未激活的世界书。历史检索是按文字线索匹配的，可能遗漏没有明显共同词语的隐含关联；检查报告也不能保证找全所有跨章节问题。

## 工作台小技巧

- 工作台可以拖动边缘调整宽度，也可以最大化。
- 点击最小化按钮可将工作台缩成悬浮气泡；生成仍会继续，点击气泡可恢复。
- 生成时间较长时可点击「取消生成」。已收到的有效正文会尽可能保留为不完整候选。
- 如果候选看起来像摘要、缺少大段原文或没有真正执行修改，不要应用；可继续提出要求或从原文开始新任务。
- 修改历史消息不会自动重写它后面的消息。若后文因此冲突，需要再单独调整后续内容。

## 常见问题

**候选为什么把一段分成多张卡？** 逐块对照会按原文段落、未修改内容和修改类别划分。连续的新增或删除会合并展示；跨过未修改段或修改类别不同时仍会分开。

**检查次数和生成次数是多少？** 普通检查一次模型调用；发现明确问题后通常再调用一次生成修订候选。若检查需要补查历史，会额外复核一次。长文续接、格式重试等也可能增加调用。

**为什么检查报告里有“待确认”？** 当前上下文或检索到的历史没有足够证据确认。你可以补充长期检查要求或本轮要求，再重新检查；不确定的项目不会自动进入修订指令。

**为什么生成会停住或只返回少量内容？** 扩展会检测空正文、极短回复和缺少结束标记的情况，并有限重试或保留部分候选。若反复发生，可检查当前连接的推理/正文设置、降低单次请求负担，或换一个稳定的模型后重试。扩展不会替你修改全局预设。

**如何回到旧版本？** 主要修改会保存为新的 SillyTavern Swipe。使用酒馆原生的 Swipe 控件切回旧版本即可。

## 诊断记录与隐私

扩展可在高级设置中保存最近 30 次本地生成诊断，并导出 JSON。记录用于查看调用阶段、耗时、响应长度、检索数量和失败类型，不保存故事正文、完整提示词、世界书内容、推理内容或 API 密钥。诊断记录保存在当前浏览器中；清除浏览器本地数据可能会移除这些记录。

## 当前限制

- 只处理普通 AI 回复，不处理用户消息、系统消息或跨消息选区。
- 选区编辑只支持一个连续选区。
- 复杂 HTML、自定义渲染或非常规 Markdown 可能无法准确映射选区。
- 检查与历史检索受本轮可用上下文及检索预算限制，不等于完整搜索和核对所有聊天历史。
- AI 检查和修改仍可能漏判或误判；请查看报告、原文和候选，再决定是否应用。
- 大幅调换段落顺序时，对照可能显示成删除和新增。

# v0.7.1 表格选区修复

## 问题

SillyTavern 会把 Markdown 表格渲染成 HTML 表格。浏览器复制或读取跨单元格选区时，单元格之间表现为制表符或换行；原始消息里对应位置却是竖线、对齐分隔行和 Markdown 留白。旧映射器按连续可见正文查找，因此跨单元格拖选会定位失败，最终不显示“修改”按钮。

截图中的另一项影响因素是右侧工作台已经打开。旧版为避免覆盖当前会话，在工作台存在时直接禁止捕获任何新选区，用户无法在不关闭工作台的情况下更换目标。

## 修复策略

1. 识别由表头、对齐分隔行和数据行组成的 Markdown 表格块。
2. 将表格竖线投影为单元格空白，将不参与渲染的对齐分隔行从可见文本投影中移除。
3. 对原生 HTML 的单元格、行和常见块级闭合标签补充可见空白边界。
4. 保留每个可见字符到原始消息的偏移映射，生成候选和最终替换仍以原始 Markdown 范围为准。
5. 空闲工作台打开时允许重新圈选；开始新的修改时继承尚未提交的修改要求和保留约束。模型正在生成时仍禁止切换，避免误取消当前任务。

## 验收范围

- 普通段落、强调、链接、引号与换行映射保持原行为。
- 跨 Markdown 表头和多行数据的选区可以定位。
- 跨原生 HTML 表格单元格的选区可以定位。
- 表格对齐分隔行不会被误当作用户选中的正文。
- 长距离拖选和滚动后的按钮恢复机制不回退。
- 工作台打开但未生成时，可以选择新目标并继续使用原有要求。

## 边界

- 仍只支持单条 AI 消息内的一个连续选区。
- 插件自定义组件若完全改写 `display_text`，仍会按现有安全规则拒绝映射。
- 非标准表格语法或由其他扩展生成、且无法回溯到原始消息的交互组件，可能仍需单独适配。

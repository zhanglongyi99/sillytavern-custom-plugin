# v0.6.2 推理通道与正文安全恢复设计

## 1. 近期故障链总结

### 1.1 续接请求永久等待

长正文自动续接曾停在“正在自动续接第 N 段”，底层连接存在但不再收发数据。v0.6.1 已增加单次调用超时、即时取消和分段检查点，解决了永久等待与已有正文全部丢失的问题。

### 1.2 未知结束原因被误报为响应上限

quiet generation 不稳定提供供应商 finish reason。旧实现把“未收到正文结束标记”直接写成“达到单次响应上限”。v0.6.1 已改成事实性文案，并区分总预算、分段上限、超时和取消。

### 1.3 正文被当作推理清空

当前完整正文调用设置了 `removeReasoning: false`，本意是保留原始响应；但返回后又调用酒馆当前推理模板的 `parseReasoningFromString`。当预设或模型把整份文章包进推理通道时，该解析器可能得到“推理非空、正文为空”，插件随后把整个响应清空。

之后 `parseRevisionTextSegment` 还会清理常见 `<analysis>`、`<thinking>` 等标签。两层清理导致模型实际返回过字符，但插件仍判定“只有推理或空内容”，并重复请求。v0.6.1 的恢复机制会保留此前检查点，却不能消除这个根因。

### 1.4 阶段提示不够明确

“候选已保留，但后续生成中断”没有说明：保留的是第一轮初稿，失败的是完整性修复重试。用户容易误以为同一次调用既成功又失败。

## 2. 产品目标

- 不依赖某个模型、预设、角色卡或固定推理标签。
- 不把真实思维过程直接放进可保存候选。
- 模型按正文协议输出后，即使外层被推理标签包裹，也能可靠提取正文。
- 酒馆推理模板只作为解析信号，不再拥有无条件清空完整响应的权力。
- 明确显示“初稿”“续接”“完整性修复”各阶段，错误必须指出失败阶段。
- 保持 v0.6.1 的超时、取消和部分候选恢复能力。

## 3. 明确正文协议

完整正文及每个续接段新增起始标记：

```text
[[STORY_REWRITER_BODY_BEGIN]]
正文……
[[STORY_REWRITER_END]]
```

- `BODY_BEGIN` 表示其后的内容是用户可见正文，不是推理。
- `END` 仍表示全文真正结束；续接未完成时可以暂不返回 `END`。
- 起始标记允许位于模型或预设添加的推理包装内部，插件应先识别自己的正文协议，再处理外层包装。
- 标记只用于传输，不进入候选。

## 4. 安全解析优先级

完整正文响应按以下顺序处理：

1. 存在 `BODY_BEGIN`：提取其后正文，遇到 `END` 截止；这是最高优先级的明确正文证据。
2. 存在 `<final>...</final>`：提取 final 内容，再识别 `END`。
3. 酒馆推理模板识别到“推理 + 正文”：只解析其正文部分。
4. 酒馆模板没有识别到推理：按普通纯文本处理，并清理完整闭合的常见推理块。
5. 酒馆模板把整个响应判为推理且正文为空：只有推理区域内部存在 `BODY_BEGIN` 或 `<final>` 时才恢复；否则保持为空并触发一次协议强化重试。

禁止仅因为“推理区域文字像文章”就直接恢复，避免把真正的隐藏推理暴露给用户。

## 5. 重试与阶段信息

- 初稿第一次为空：提示“初稿未找到明确正文，正在使用正文边界协议重试”。
- 续接为空：提示具体续接段号。
- 完整性修复为空：明确写出“完整性修复阶段”，不把它描述成初稿失败。
- 如果完整性修复失败但初稿检查点存在：保留初稿，并说明初稿为何触发修复、修复为何中断。
- 日志增加 `stage`、`parseOutcome`、`providerCharacters` 和 `usableCharacters`，仍不得记录正文、提示词或推理内容。

## 6. 通用性边界

- 不维护模型名称白名单。
- 不读取或修改用户预设、角色卡、世界书。
- 不猜测某种自然语言是思考还是正文。
- 酒馆当前推理模板、常见显式标签和插件正文协议是能力式解析层，按证据降级。
- 没有明确正文证据时宁可保留已有检查点并让用户决定，也不泄露疑似推理。

## 7. 验收标准

- 普通纯文本正文与旧版 `END` 协议继续可解析。
- `<think>推理</think> + 正文` 只保留正文。
- 整份响应被 `<analysis>` 或自定义推理模板包裹，但内部带 `BODY_BEGIN` 时能恢复正文。
- 整份未闭合推理且没有正文标记时仍返回空，不泄露推理。
- 酒馆解析器返回“推理非空、正文为空”时不再先行销毁原始响应。
- 初稿失败与完整性修复失败使用不同状态文案。
- 完整性修复失败时第一轮检查点仍可逐块确认。
- 超时、取消、Swipe、逐块确认和通用上下文测试继续通过。

## 8. 发布

- 目标版本：`0.6.2`。
- 不新增用户设置，不改变设置 schema 版本。

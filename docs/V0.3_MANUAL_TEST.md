# v0.3 手工验证清单

自动测试不把插件复制到本地 SillyTavern。本清单用于用户通过 Git URL 更新扩展后，在实际聊天界面验证浏览器交互和当前模型兼容性。

## 准备

- 使用非关键聊天，或先备份聊天。
- 确认扩展列表显示“故事改写 0.3.0”。
- 首轮保持“完整酒馆上下文”和“语义关联”。
- 准备一条至少包含三个段落、两个人物和一处前后伏笔的 AI 回复。

## 1. 精确替换回归

1. 选中 AI 回复中的一句话。
2. 确认浮动工具条同时显示“精确替换”和“柔性重构”。
3. 选择“精确替换”，生成候选并确认。
4. 确认只有选区对应的原始 Markdown 被替换。
5. 使用提示条或消息工具栏撤销，确认原文恢复。

## 2. 柔性选区重构

1. 粗略选择涉及某个人物线的一个或两个段落。
2. 选择“柔性重构”，输入跨段要求。
3. 确认状态依次经过资料检索、影响分析、完整生成和审计。
4. 确认“重点变化”能区分强修改、关联修改、衔接调整和疑似越界。
5. 切换到“完整候选稿”，确认输出是完整消息而非局部补丁。
6. 切换到“参考与影响范围”，确认来源名称与实际聊天或设定一致。

## 3. 影响范围确认

1. 在设置中开启“生成前确认 Agent 识别的影响范围”。
2. 再次执行柔性重构。
3. 在影响分析后取消一个圈外关联段落。
4. 点击“继续生成完整候选”。
5. 确认取消的区域没有被当作允许修改区。
6. 改变影响强度、修改要求或持续约束，确认旧影响计划被标记失效并要求重新分析。

## 4. 全文方向重构

1. 不选择文字，点击 AI 消息工具栏的魔杖按钮。
2. 输入“重新梳理某人物线，其他人物与设定保持不变”。
3. 确认工作台标题为“故事全文重构”。
4. 确认完整候选可以保存为新 Swipe。

## 5. Swipe 安全

1. 记录原消息当前 Swipe 数量和文本。
2. 保存柔性或全文候选为新 Swipe。
3. 确认 Swipe 数量增加一，候选成为当前版本。
4. 切回旧 Swipe，确认原回复与原有消息元数据仍然存在。
5. 刷新页面，确认新 Swipe 仍然存在。

## 6. 并发保护

1. 打开重构工作台但暂不保存。
2. 在另一个操作中切换该消息 Swipe，或编辑原消息。
3. 返回工作台尝试保存。
4. 确认插件拒绝写回，并提示原消息、聊天或 Swipe 已变化。
5. 在工作台打开期间切换到另一个聊天，重复确认不会写入新聊天。

## 7. 输出隔离

使用容易输出分析标签的模型执行重构，确认以下内容不会进入候选框：

- `<think>`、`<analysis>`、`<reasoning>`。
- `<system-reminder>`。
- `<story_rewriter_...>`。
- `[P001]` 等内部段落编号。
- “只输出符合 Schema 的 JSON”等编辑契约。

若模型连续两次没有返回有效 JSON，应看到失败提示，聊天内容保持不变。

## 8. 上下文与资料降级

1. 分别测试“完整酒馆上下文”和“局部快速模式”。
2. 确认局部快速模式明确说明不会使用完整酒馆提示链。
3. 使用一个有关联角色世界书的聊天，确认来源列表能出现对应资料。
4. 使用没有命中资料的要求，确认插件提示未检索到额外资料，而不是宣称不存在相关设定。

## 9. 长回复与阻断

1. 对长回复执行全文重构，确认完整候选 Token 上限生效。
2. 若输出明显少于原文，确认审计以疑似截断阻止保存。
3. 故意要求模型大幅改写圈外无关段落，确认出现红色变化和阻断或明确警告。
4. 手动修改候选后，确认审计结果会即时更新。

## 10. 移动端与窄窗口

1. 将浏览器窗口缩窄到 700px 以下。
2. 确认工作台占满宽度，文本区域可以滚动。
3. 确认浮动选区工具条的两个图标均可点击。
4. 确认底部生成、保存和取消按钮不会被遮挡。

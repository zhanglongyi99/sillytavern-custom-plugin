# v0.7.6 多轮有效修改校验

## 问题

旧流程在“继续当前版本”时同时使用两套基准：正文生成把当前候选放在 `previousDraft`，影响分析、段落编号、逐块审核和完整性检查仍基于最初消息。模型原样返回当前候选时，长度与结束标记检查仍会通过，逐块审核又会重复展示上一轮相对原文的变化，导致零改动结果被记录为成功轮次。

局部精确替换也只检查结果是否为空，没有拒绝与本轮工作稿相同的替换。

## 修改

1. 每轮建立唯一 `generationBaseline`：选择“继续当前版本”时使用当前合成稿，选择“从原文开始新任务”时使用最初消息。
2. 影响分析、段落编号、完整性检查、正文生成与本轮逐块审核统一使用该基线。
3. 选区来自最初消息时，通过段落对齐把原选区映射到当前候选；一段扩成多段时保留全部相关目标段。
4. 当前候选已经承载旧轮次结果，不再重复注入旧轮次自然语言要求；持续约束仍单独注入。
5. 新增有效修改校验：候选必须与本轮基线不同，并且 focus 区至少产生一项变化。只修改保护区不算完成任务。
6. 无有效修改时自动使用强化契约重试一次；再次失败则恢复上一有效候选，不新增成功轮次。
7. 局部精确替换同样拒绝与当前替换稿相同的结果，并自动重试一次。
8. 诊断日志新增基线/候选短指纹、等价状态、相似度、重点区与计划内变化数量、重试原因；仍不保存正文或完整提示词。

## 用户可见行为

- 第二轮“重新构思”“换一种方案”等要求不再被第一轮 Diff 冒充为已完成。
- 逐块确认显示当前轮真正产生的变化；此前已确认的修改作为未变化基线保留。
- 模型连续两次原样返回时显示失败状态，上一有效候选保持不变。
- 用户仍可切换“从原文开始新任务”，清除当前候选与旧轮次影响。

## 验收

- 全文候选与本轮基线相同：拒绝并重试。
- 只修改保护区、focus 区未变化：拒绝并重试。
- focus 区产生实质变化：进入逐块确认。
- 一段在上一轮扩成多段：下一轮原选区能够映射到全部新段落。
- 精确局部候选与当前替换稿相同：拒绝并重试。
- 重试仍无变化：不覆盖候选，不新增成功轮次。
- 日志能够区分无变化、目标区未变化与有效修改，且不包含故事正文。

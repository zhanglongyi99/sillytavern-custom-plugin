# v0.7.4 表格选区结构空白兼容

## 问题复盘

v0.7.3 修复了跨视口拖选后丢失释放事件的问题，但按钮恢复还要通过“可见选区映射回原始消息”这道安全检查。浏览器对 HTML 表格的 `Range.toString()` 没有统一的单元格分隔行为：有的插入制表符或换行，有的把相邻单元格文本直接拼接。原始消息中的 Markdown 表格则使用竖线和对齐分隔行，因此严格文本匹配仍可能失败。

## 处理方案

1. 首先保留原有的空白敏感匹配，普通正文与常见表格路径不改变。
2. 仅当严格匹配失败时，启用忽略结构空白的第二次定位。
3. 第二次定位仍保留每个可见字符到原始 Markdown 字符的映射，并使用选区在消息中的可见起点消除重复文本歧义。
4. 最终替换范围继续指向原始 Markdown，不把渲染后的 HTML 或压缩文本写回消息。
5. 修正单个 `~` 被误判为删除线标记的问题；时间范围等可见文本保留，只有成对的 `~~` 作为格式标记移除。

## 验收范围

- 表格单元格以制表符、换行或无分隔符返回时均可定位。
- 从普通段落或折叠标题开始、在表格单元格中结束的跨块选区可以定位。
- Markdown 表格对齐分隔行不会进入候选正文。
- 普通正文优先使用原有严格路径。
- 映射失败时仍不允许猜测替换位置。

## 边界

若其他扩展实际改写了显示正文，使其与消息原文不再对应，插件仍会拒绝替换；这与浏览器仅改变表格结构空白的情况不同。

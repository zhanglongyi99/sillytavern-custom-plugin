# v0.7.5 水平分隔线选区兼容

## 真实复现结论

在 Edge 中读取失败现场时，DOM 选区完整存在，按钮节点存在且没有控制台异常。使用该消息的原始 Markdown 与可见选区离线复跑，定位在选区第 2025 个可见字符处失败：原文包含 `---` 水平分隔线，浏览器将其渲染成无文字的 `<hr>`，旧投影却错误保留了三个短横线。

快速向下跨页拖选更容易穿过一个或多个水平分隔线，因此表面上像滚动恢复失效，实际是恢复后的原文定位被安全检查拒绝。

## 修复

1. 在行首识别 Markdown 标准水平分隔线：连续短横线、星号或下划线，允许规范内的空格。
2. 将分隔线视为无可见文字的结构节点，同时保留其在最终原始范围内部的位置。
3. 不改变普通句子中的短横线、星号和下划线。
4. 增加从普通正文跨两种水平分隔线并结束在编号列表中的回归测试。

## 验收

- 长选区穿过 `---`、`***`、`___` 或带空格的等价写法时可以定位。
- 最终原始范围仍包含被跨过的 Markdown 分隔线。
- 普通列表、强调、表格、单个 `~` 与跨视口稳定恢复继续通过测试。

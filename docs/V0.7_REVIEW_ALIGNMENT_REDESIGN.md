# v0.7 长文本对照与对齐重构

## 1. 用户问题

当前“逐块确认”同时暴露了算法问题和界面问题：

- 一段大幅新增内容会被强行配给某个无关原文段落；
- 单换行、列表和长篇规划文本容易产生几十甚至上百个变化卡片；
- 等宽双栏把每栏压得过窄，中文长文本阅读与滚动成本很高；
- 复选框表达的是“采用新版”，但视觉上不如明确的二选一决策直观；
- 批量按钮在窄宽度下被压成竖排，重要操作和阅读区域争夺空间；
- 用户无法快速只看待确认项，也无法把工作台一键放大。

核心任务不是展示最小字符差异，而是让用户可靠回答：这块新版是否应该替换这块原文？

## 2. 现有算法缺陷

现有段落动态规划的替换成本范围为 `0–1.35`，删除和新增各为 `1`。因此两个完全无关的段落仍然比“删除旧段 + 新增新段”更便宜，算法天然倾向于错误配对。

同时，算法只支持 `1↔1`、`1↔0`、`0↔1`，不支持故事改写中常见的：

- 一个旧段扩写成多个新段；
- 多个旧段重新梳理为一个新段；
- 在两个保持不变的锚点之间整体重写一组内容。

## 3. 成熟方案参考

- Git 提供 Myers、minimal、Patience 和 Histogram；Histogram 在 Patience 基础上利用低频共同元素，适合重复内容较多的文本。
- Beyond Compare 提供 Standard、Myers O(ND)、Patience Diff，也允许“Never align differences”，即宁可显示成增删块，也不强行把不相似内容标为一一修改。
- Google diff-match-patch 使用 Myers，并通过 semantic cleanup 把机器最短但人类难读的碎差异整理为更易理解的块。

参考链接：

- https://git-scm.com/docs/git-diff
- https://www.scootersoftware.com/BCompare.pdf
- https://github.com/google/diff-match-patch

本插件是无构建依赖的 SillyTavern 前端扩展，不直接引入大型 diff 运行库。实现采用上述原则，而不是复制某个工具的逐行行为。

## 4. 新对齐管线

### 4.1 稳定锚点

先寻找原文与候选中标准化后完全相同、且在两边都只出现一次的段落。使用 Patience 风格的最长递增子序列保留顺序稳定的唯一锚点。

锚点的意义：保持不变的玛修段落会把前后改写区域隔开，避免贞德新增内容跨越锚点错配到玛修。

### 4.2 模糊段落组对齐

只在相邻锚点之间运行带权动态规划，支持：

- `1↔1` 修改；
- `1↔2`、`1↔3` 扩写；
- `2↔1`、`3↔1` 合并；
- 独立新增和删除。

相似度综合字符 n-gram、检索词元、长度比例和首尾线索。完全无关的替换成本必须不低于“删除+新增”，从根本上取消强行配对。

### 4.3 人类可读变化块

相邻的纯新增/纯删除与同一区域修改合并成一个 review hunk，但设置字符和段落数量上限，避免整个长篇只剩一个不可分割的大块。

每个 hunk 保存原文段落范围、候选段落范围、锚点位置和组成操作。展示、勾选和最终合成必须使用同一个 hunk 列表，禁止分别重新推导 ID。

### 4.4 安全合成

- 采用 hunk：写入候选组；
- 保留 hunk：写入原文组；
- 纯新增未采用：不写入；
- 纯删除未采用：保留原文；
- 未变化锚点始终只写一次。

## 5. 新审核界面

### 5.1 更大的工作区

- 桌面默认宽度从 760px 提升到约 960px；
- 标题栏增加“最大化/还原”，最大化时占据浏览器可用区域；
- 仍保留左缘拖动调整宽度；
- 移动端保持全屏单栏。

### 5.2 阅读模式

逐块确认默认采用上下堆叠，而不是强制等宽双栏：

- 上方是“原文”，默认折叠长内容；
- 下方是“新版”，完整展示；
- 用户可切换“上下对照 / 左右对照”；
- 左右模式只在足够宽时启用，卡片内部滚动不再限制为 15em。

### 5.3 决策控件

每张卡使用明确的二选一分段按钮：

- `保留原文`
- `采用新版`

状态文字直接显示“将采用新版”或“将保留原文”，不再依赖一个孤立复选框。

### 5.4 导航和降噪

- 顶部显示 `已确认 / 总变化块`，而不是把已采用数量误当成确认进度；
- 支持筛选“全部 / 计划内 / 疑似越界”；
- 支持“上一个 / 下一个”快速跳转；
- 批量操作使用紧凑按钮，不允许被压成逐字竖排；
- 相邻不变内容不生成卡片。

## 6. 兼容与边界

- 不改变模型调用、上下文、世界书、生成提示词、自动续写或诊断日志。
- 不依赖语言、角色卡、模型或预设关键词。
- 保留旧会话候选恢复能力；恢复时重新使用新版对齐管线审计。
- 大幅调换段落顺序仍不等同于真正的 moved-block 检测；本版优先保证不强行错配和安全合成。
- v0.7 首版不做逐字彩色高亮。先保证块定位、决策和合成正确，再根据真实使用决定是否增加 semantic word diff。

## 7. 验收标准

- 头部新增一段内容不会导致后续所有段落错位。
- 一个旧段扩成三段时形成一个可独立采用的变化块。
- 三个旧段合并为一个新段时能完整保留或完整采用。
- 完全无关的段落不会被标为高相似度 `1↔1` 修改。
- 展示的 hunk ID 与合成使用的 hunk ID 来自同一对齐结果。
- 93 个逐行碎变化的典型长文本显著收敛为少量语义区域。
- 默认工作台更宽，最大化可用，上下对照可读，批量按钮保持横排。
- 现有生成、Swipe、逐块采用、全部采用和全部保留原文测试继续通过。

## 8. 发布计划

- 目标版本：`0.7.0`。
- 第一阶段：对齐管线、共享 hunk 模型与回归测试。
- 第二阶段：审核 UI、最大化、阅读模式和筛选导航。
- 不加入新的模型调用，不以更高费用换取对齐。

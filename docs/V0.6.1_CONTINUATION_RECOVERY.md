# v0.6.1 续接超时与部分候选恢复设计

## 1. 事故表现

完整候选在自动续接时长期停留在“正在自动续接第 N 段”。现场检查显示浏览器到 SillyTavern、SillyTavern 到模型接口的 TCP 连接仍处于建立状态，但服务端 CPU 与收发字节长期没有变化。

当前实现存在三个相互放大的问题：

1. `generateQuietPrompt` / `generateRaw` 没有插件级超时，失去响应的请求可以永久阻塞。
2. 只要模型没有返回 `[[STORY_REWRITER_END]]`，界面就宣称“达到单次响应上限”；实际上插件不知道真实 finish reason，也可能只是模型忽略了结束标记。
3. 已完成的分段正文只保存在 `runRevision` 局部变量中。超时、取消或页面刷新前不会进入候选区，用户无法抢救已经生成的内容。

## 2. 产品目标

- 任意一次模型调用都必须在有限时间内完成、报错或被取消。
- 用户点击取消后，插件自身应立即结束等待，不依赖底层接口是否正确收尾。
- 每个有效分段都成为会话检查点；后续分段失败时仍可进入逐块审阅。
- “未收到结束标记”和“确认达到接口上限”必须分开表达。
- 日志足以回答：第几阶段、第几段、第几次尝试、请求预算、耗时、返回字符数、是否收到结束标记、为何停止。
- 不增加普通工作台的决策负担；超时秒数只放在高级设置。

## 3. 调用守卫

新增统一的 `runGenerationCall`：

- 输入：会话、阶段名、调用函数、超时毫秒数和诊断元数据。
- 同时等待模型 Promise、超时 Promise 和会话取消 Promise。
- 超时默认 180 秒，可在高级设置中调整为 30–900 秒。
- 超时后调用 SillyTavern `stopGeneration()`，并抛出可识别的 `GenerationTimeoutError`。
- 取消通过每轮独立 `AbortController` 立即打断插件等待；同时调用 `stopGeneration()`。
- 旧模型 Promise 即使稍后返回，也不能再改变当前会话或候选。

该守卫用于：精确替换、影响分析和完整正文，避免其他阶段出现同类永久等待。

## 4. 分段检查点

完整正文每收到一个非空分段后立即写入：

- `session.partialCandidate`
- `session.generationSegments`
- `session.generationDiagnostics`

如果后续发生超时、取消、空响应或其他异常：

- 有检查点：将已有正文作为“不完整候选”送入原有逐块审阅流程；不自动保存。
- 无检查点：显示普通失败信息。
- 部分候选必须携带醒目的失败原因，所有删除类变化默认不采用。

开始覆盖式的“完整性修复重试”前保留第一轮检查点；第二轮只有产生更长的有效结果时才替换检查点。

## 5. 结束判断与文案

扩展通过 quiet generation 无法稳定取得供应商 finish reason。因此：

- 找到结束标记：`completed`。
- 没有结束标记但还有预算：`marker_missing`，只表示“模型未声明正文结束”。
- 总预算不足：`budget_exhausted`。
- 达到最多分段数：`segment_limit`。
- 调用超时：`timeout`。
- 用户取消：`cancelled`。

界面不得再把 `marker_missing` 写成“达到单次响应上限”。续接文案改为：

> 第 N 段未返回正文结束标记，正在请求后续内容……

## 6. 诊断日志

控制台统一使用 `[Story Rewriter][generation]` 前缀，每次调用记录：

- `event`: `start | success | timeout | cancelled | error | checkpoint`
- `stage`
- `segment`
- `attempt`
- `responseLength`
- `promptTokens`
- `elapsedMs`
- `responseCharacters`
- `complete`

日志不得包含完整提示词、世界书正文、聊天内容或 API 凭据。

## 7. 设置迁移

- 设置版本由 6 升至 7。
- 新增 `generationTimeoutSeconds`，默认 180。
- 旧设置无损迁移；其他预算与开关保持原值。
- 发布版本：`0.6.1`。

## 8. 验收标准

- 永不返回的生成 Promise 在设定时间后结束插件等待并调用 `stopGeneration()`。
- 点击取消无需等待模型 Promise 返回。
- 第 2 段超时后，第 1 段仍出现在候选预览和逐块审阅中。
- 取消发生在已有检查点后，同样保留部分候选。
- 没有结束标记时不再显示“达到单次响应上限”。
- 超时前后的日志不泄露正文或提示词。
- 旧设置自动得到 180 秒默认值。
- 现有 Swipe、撤销、逐块确认和完整性审计测试继续通过。

# 审阅修订可靠性优化

## 两次实验

一次自动修订仅返回原文长度的 7.74%；随后审阅修订虽然返回 95.4% 长度，但差异包含一个重点块和四个保护块。长度、发生变化不等于语义问题解决。现有日志无法证明是推理开关导致失败。

## 实施范围

- 始终保留完整待审章和当前要求；历史证据统一预算、去重、移除检索内部元数据。最近六条消息不再无预算追加。
- 补查仍受预算控制，优先保留已引用证据；修订仅传递确认问题引用的资料，长资料保留引用周边。
- 自动审阅修订逐项核对目标及关联段落是否有差异；这只是机械检查，不声称语义修复成功。缺少目标变化时保留候选供确认，明确列出未变化目标。
- 不自动接受计划外修改，继续使用现有对照决策；报告保护区变化数量，并提示保留原文可能影响跨段修复。
- 修正无进展提示，区分首段不足与续接无进展，不归因于未观测到的推理路由；长度比明确不等于内容覆盖率。
- 日志补充资料裁剪、逐项检查和重试策略元数据，不记录故事全文。

## 验证

预算边界、资料去重、完整章保留、引用周边、关联目标遗漏、合并差异块、未确认问题隔离；运行全部现有测试和语法检查。真实模型语义效果仍需实用验证。不新增默认模型调用，不改预设、不绑定模型或角色。

验证结果：107 项测试通过，语法及入口导入检查通过。逐项检查基于段落差异，只能提示目标是否检测到变化，不证明语义修复正确；合并改写的精确归属仍需人工核对。没有调用真实模型，也没有自动推送或覆盖酒馆已安装目录。

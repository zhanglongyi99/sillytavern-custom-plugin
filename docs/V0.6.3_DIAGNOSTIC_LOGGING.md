# v0.6.3 持久诊断日志设计

## 1. 决策

本版本不改变故事改写的核心工作流，不减少完整上下文，不关闭世界书激活，不取消影响分析、自动续接或完整性修复。成本优化必须等待真实使用数据，不能仅凭缓存命中率猜测后牺牲准确度。

本版本只增加隐私安全、可导出的本地诊断记录，用于回答：

- 一次用户操作实际调用模型多少次？
- 时间主要消耗在影响分析、初稿、续接还是完整性修复？
- 哪些调用返回空内容、只有推理或正文协议内容？
- 插件自己的提示词结构何时发生变化？
- 请求预算、供应商返回字符数、最终可用字符数分别是多少？
- 超时、取消、格式重试和完整性修复各发生多少次？

## 2. 明确不能记录的内容

诊断记录禁止包含：

- 聊天正文、候选正文和选区文字；
- 完整提示词、角色卡、世界书、作者注和检索资料；
- API Key、请求头、服务器地址和账号信息；
- 模型推理内容；
- 可逆推出正文的长片段或序列化载荷。

允许记录不可逆的短哈希，用于判断插件提示结构是否相同。哈希只覆盖插件构造的 quiet prompt；SillyTavern 最终发送给供应商的完整提示链目前没有通过公开接口返回，因此日志不能伪装成真实供应商缓存统计。

## 3. 归档格式

使用浏览器当前 SillyTavern 站点的 `localStorage` 保存版本化 JSON：

```json
{
  "schemaVersion": 1,
  "exportedAt": "...",
  "capabilities": {
    "providerCacheUsage": "unavailable_from_quiet_generation_api"
  },
  "runs": []
}
```

每次点击“生成新版本”建立一个 run：

- `id`、开始/结束时间、最终状态；
- 插件版本、修改模式、范围模式、上下文模式；
- 当前预设上下文上限和响应上限；
- 相关资料条数和字符预算；
- 事件列表与汇总统计。

每个事件只记录白名单字段：

- `event`、`stage`、`segment`、`attempt`；
- `responseLength`、`promptTokens`、`pluginPromptCharacters`；
- `pluginPromptFingerprint`；
- `elapsedMs`、`providerCharacters`、`usableCharacters`；
- `parseOutcome`、`complete`、`stopReason`、`errorCode`；
- `coverageRatio`、`retrievalItems`。

## 4. 生命周期与容量

- 默认启用诊断记录。
- 每个生成事件立即写入，页面刷新或请求卡死后仍能看到此前事件。
- 最多保留最近 30 次生成，每次最多 100 个事件。
- 超出容量按最旧 run、最旧 event 自动裁剪。
- localStorage 不可用或配额不足时不得影响生成，只在控制台给出一次警告。
- 关闭记录后不再新增数据，但不会自动删除旧记录。

## 5. 用户界面

高级设置新增“诊断记录”：

- `保存隐私安全的诊断记录` 开关；
- 当前已保存 run 数量；
- `导出诊断记录`：下载格式化 JSON；
- `清空诊断记录`：明确确认后删除本地归档。

导出文件名包含时间，不包含角色、聊天或模型名称。界面必须明确说明记录中不含正文、提示词、世界书、推理或密钥。

## 6. 分析边界

本日志可以分析调用次数、阶段耗时、结构变化和空响应比例，但不能直接读取供应商的 cached input tokens。后续分析缓存问题时，需要把本日志与供应商账单或使用量面板中的缓存 Token 指标按时间对照。

## 7. 验收标准

- 正常智能关联任务形成一个 run，影响分析与正文调用属于同一 run。
- 初稿续接、空正文重试和完整性修复有独立阶段事件。
- 取消、超时、成功和保留部分候选均有结束状态。
- 页面刷新后归档仍存在并可导出。
- 第 31 次生成自动删除最旧 run。
- 单次第 101 个事件自动删除最旧事件。
- localStorage 写入失败不影响生成。
- 导出 JSON 中不出现测试正文、提示词、世界书或 API Key。
- 现有完整上下文、推理安全解析、Swipe 和逐块确认行为不变。

- 发布版本：`0.6.3`。
- 设置 schema：7 升至 8，新增 `diagnosticsEnabled`，默认 `true`。

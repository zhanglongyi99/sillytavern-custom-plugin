# 完整候选预算修复

2026-10-27：最近一轮日志记录单次预设上限 100000，但初稿请求只分配 8570。
第二次尝试返回 13325 字符，没有结束标记，第一段之后直接 budget_exhausted。
旧代码把原文 token × 1.15 + 256 的输出估算同时当作合并正文上限；因此常常没有剩余额度续写。

现在单次估算仍用于控制请求大小，累计正文上限则使用用户设置的 fullResponseLength（默认 32768）。
不自动修改用户额度，不把结束标记缺失判成完整；最多分段数及无进展停止机制保持不变。
上下文不足、单次响应上限不足与累计正文额度耗尽分别提示。
诊断新增 estimatedOutput、totalLimit、usedTokens、remainingTokens；这些是本地正文估算，不是上游账单 token。
额度按每份候选生成流程计算；重试和重新生成修复稿并非同一付费总账。

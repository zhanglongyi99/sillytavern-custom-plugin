# v0.7.9 空续接熔断与推理通道诊断

## 问题

本地诊断记录显示，部分模型或兼容服务会在请求成功后只返回推理通道、空正文或几十字的确认语。旧状态机会把每次响应都计作一个有效分段，即使没有新增正文，因此界面会连续跳过分段并最多发出八轮续接请求。

这不是上下文不足：日志中的失败请求通常在约 1–2 秒内返回 0–50 个字符，而正常长文请求会运行数十秒并返回上万字符。

## 产品规则

1. 只有收到正文结束标记，或收到足够长的正文增量，才算完成一个分段。
2. 首段采用与原文规模相关的最低进展门槛；续接段采用较小固定门槛。带结束标记的短尾仍然有效。
3. 空正文、纯推理和极短非正文会使用强化边界协议重试一次，但不消耗分段编号。
4. 连续两次无进展后立即熔断。已有正文则保留为不完整候选；没有正文则给出明确错误。
5. 不完整且覆盖不足的候选先进入失败尝试，不再触发“有效修改修复”，避免把上游空响应放大成另一组昂贵调用。
6. 诊断日志仅记录长度、分类、门槛和指纹，不记录故事正文或提示词。

## 兼容策略

实现不识别或绑定特定模型名称。它只根据可观察响应判断是否产生正文进展，因此对 DeepSeek、OpenAI 兼容接口、本地模型和其他预设采用同一规则。

当模型连续只返回推理/空正文时，界面建议关闭当前连接的“请求模型推理”后重试。插件不会自动修改酒馆全局预设，避免影响其他聊天或并发生成。

## 验收标准

- 两次空响应不会从第 2 段跳到第 3 段，更不会空跑到第 8 段。
- 数十字且没有结束标记的确认语不会被当成文章首段。
- 已有长正文后收到带结束标记的短尾可以正常完成。
- 覆盖不足的残片不会触发有效修改重试。
- 诊断导出可以区分 `reasoning_only`、`empty` 与 `insufficient_progress`。

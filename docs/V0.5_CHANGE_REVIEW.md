# v0.5 逐块采用与长文本审阅规格

## 1. 问题定义

当前流程把模型生成的完整候选视为一个不可拆分的整体。模型在第二轮调整时，即使只收到一个局部要求，也可能重新措辞其他段落；用户只能全部采用、手工复制或全部放弃。现有“查看修改”已经能按段落展示差异，却没有把这些差异变成可操作的决策单元。

长文本场景还存在两个界面问题：固定 640px 的侧栏偏窄；“原文/候选”双栏会把每栏进一步压缩，而且短 textarea 迫使用户在多个嵌套滚动区之间移动。

## 2. 核心用户目标

用户不是要约束模型只能生成局部补丁，而是要：

1. 让模型先提出一份完整、上下文一致的修改方案。
2. 清楚看到模型实际改变了哪些块。
3. 对每一块独立决定“采用候选”或“保留原文”。
4. 在保存前看到这些决定合成后的完整文章。
5. 面对长文本时仍能舒适阅读、编辑和返回聊天。

## 3. 产品模型

候选不再只有一个文本值，而分为三层：

- **原文基线**：打开工作台时捕获的当前消息，不随多轮生成漂移。
- **模型提案稿**：本轮模型返回的完整文本，只用于建立变更块。
- **用户合成稿**：按照每个变更块的采用状态，把提案稿与原文重新组合后的最终候选。

保存、覆盖、审计和完整预览一律针对用户合成稿。模型提案稿保留到下一轮生成或用户直接编辑完整稿为止。

## 4. 逐块采用

### 4.1 默认状态

- 强修改、关联修改、衔接调整：默认采用。
- 疑似越界：默认保留原文。
- 用户可以随时反转任何一块；审计只提示风险，不锁定选择。

这个默认值优先防止第二轮生成意外改写无关内容，同时不妨碍用户主动采用模型的额外优化。

### 4.2 操作

“逐块确认”作为生成后的默认结果页。每张差异卡提供“采用此修改”复选框，并保留原文、候选和分类。

顶部提供三个批量动作：

- `仅采用计划内`：采用强修改、关联修改和衔接调整，拒绝疑似越界。
- `全部采用`：采用模型提案稿的全部变更。
- `全部保留原文`：拒绝全部变更。

每次切换立即重建用户合成稿、更新完整预览和审计摘要，不再次调用模型。

### 4.3 合成规则

变更块沿用现有段落级 LCS 对齐：

- 修改块：采用时使用候选段落，拒绝时使用原段落。
- 删除块：采用时删除，拒绝时恢复原段落。
- 新增块：采用时插入，拒绝时忽略。
- 未变化锚点：始终使用原文段落，避免无意义的空白漂移。

首版以空行分隔的 Markdown 块重新拼接。复杂 HTML、自定义渲染和大幅段落调序仍属于已知限制。

### 4.4 手工编辑

用户在“完整预览”中直接编辑后，当前文本成为新的提案基线，重新建立变更块；因为这是用户亲自输入的内容，新识别出的块默认全部采用。模型多轮生成仍以当前合成稿作为 previousDraft，但原文基线不变。

## 5. 长文本界面

- 默认侧栏宽度提高到 760px，并允许横向拖动调整，最大不超过视口。
- 移动端仍使用全屏宽度并关闭横向缩放。
- 生成完成后默认进入“逐块确认”，而不是全文双栏。
- 完整预览只显示一个大尺寸可编辑合成稿；原文通过上方折叠区和差异卡查看。
- 合成稿最小高度使用视口比例，减少小框内滚动。
- 宽屏下差异卡的原文/候选并排，窄屏自动改为单列。
- 审阅工具栏保持清晰，显示“已采用 X/Y 项”。

## 6. 权限与安全

- 用户始终可以采用任意变更块，也可以在审计警告后保存或覆盖。
- 候选为空、源消息或 Swipe 已变化、实际写入失败时仍停止操作。
- 每次保存的元数据记录最终合成稿的审计结果；不把未采用的模型提案写入聊天。

## 7. 验收标准

1. 模型生成包含多处改动的候选后，每个差异块都可独立切换。
2. 疑似越界块默认不采用，计划内块默认采用。
3. 修改、删除、新增三类块都能正确恢复原文或采用候选。
4. 批量选择立即同步完整预览，不触发模型调用。
5. 完整预览手工编辑后重新建立审阅块，手工改动默认保留。
6. 保存的新 Swipe 与当前合成稿完全一致，原 Swipe 保留。
7. 工作台可横向调整；长文本编辑区明显高于旧版，移动端不产生横向溢出。
8. 审计高风险仍可由用户确认后保存。

## 8. 长输出协议

影响范围属于短结构化数据，继续使用严格 JSON。完整正文不再放入 JSON 字符串：正文中的换行、引号和长篇幅会放大转义开销，并在响应截断时导致整份结果无法解析。

完整正文使用带结束标记的纯文本协议：

1. 模型只输出文章正文，并在真正完成后追加内部结束标记。
2. 插件移除结束标记后再交给逐块审阅。
3. 单次响应未出现结束标记时，插件携带已生成前缀请求从断点继续，不重新生成前文。
4. 多段输出使用尾部/头部重叠检测合并，避免断点附近重复。
5. 总生成量受“完整候选最大 Token 数”约束；该预算是所有续接段之和，不是单段上限。
6. 达到总预算或续接次数上限仍未结束时，保留已生成文本并添加“可能未完整结束”的高风险审计提示，用户仍可检查、编辑或强制采用。

这套协议解决的是输出通道截断，不改变 100 万等输入上下文配置；工作台仍分别显示上下文上限与单次响应上限。

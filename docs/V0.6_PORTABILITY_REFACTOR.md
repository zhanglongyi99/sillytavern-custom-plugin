# v0.6 通用性重构设计

## 1. 背景

故事改写扩展必须能随 SillyTavern 当前连接的模型、预设、角色卡、世界书和推理模板工作。这里的“通用”不等于不同模型写出完全相同的文字，而是：

- 相同的用户选择和修改要求得到相同的权限边界；
- 事实来源遵守 SillyTavern 实际生效的上下文，不自行扩大世界书范围；
- 模型不支持 JSON Schema、改变推理标签或改变排版时，工作流仍可安全降级；
- 模型自报的置信度、提示词语言和段落空行不决定哪些内容能够被替换；
- 无法验证的候选可以展示和人工选择，但不会被误判为可靠结果。

## 2. 当前问题

### 2.1 上下文存在两个事实来源

完整上下文生成已经由 `generateQuietPrompt` 注入当前角色、聊天、作者注和实际激活的世界书。扩展又直接加载角色与聊天绑定世界书，并检索所有启用条目。这会绕过关键词、概率、递归、角色过滤、冷却和粘滞等激活规则，也会重复发送已经激活的内容。

### 2.2 角色卡字段权威过高

角色 `system_prompt`、`post_history_instructions` 被当作用户硬规则，`first_mes` 被当作已经发生的剧情。它们分别属于行为指令和创作样例，不能由扩展提升为事实。

### 2.3 输出协议依赖模型能力

影响分析与精确替换优先依赖严格 JSON。部分后端忽略 Schema、附加解释或在长 JSON 中截断。重复要求同一种 JSON 不是有效降级。

### 2.4 修改范围依赖模型置信度

固定的 `0.6/0.75/0.85` 阈值假定所有模型以相同方式校准概率。置信度只能作为解释信息，不能决定段落是否存在或用户是否有权选择它。

### 2.5 完整性依赖语言关键词

通过“精简、摘要、shorten”等词判断是否允许缩短，会遗漏其他语言和表达。长度意图必须成为任务协议中的枚举字段，无法确认时保守地保持长度。

### 2.6 推理与文本结构依赖固定格式

扩展动态导入 SillyTavern 内部推理模块并以固定标签兜底；段落只按空行切分，合成时强制使用双换行。这会受到 SillyTavern 目录变化、预设推理模板、Markdown/HTML 格式和模型换行习惯影响。

## 3. 设计原则

### 3.1 单一上下文真源

- Tavern 模式：SillyTavern 最终提示链是角色、预设和世界书的唯一生成真源。
- 扩展不再把原始角色卡或未激活世界书二次注入 Tavern 请求。
- 扩展资料库在 Tavern 模式只保留历史消息证据与用户明确规则；世界书激活来源用于展示和审计，不重新改变提示内容。
- Local 降级模式可以建立显式上下文快照，但必须区分事实、样例和指令，并优先使用 SillyTavern 的世界书激活结果。

### 3.2 权威类型

| 类型 | 含义 | 可成为硬保护 |
| --- | --- | --- |
| `user-rule` | 用户本轮要求和持续约束 | 是 |
| `fact` | 已验证的角色、世界或剧情事实 | 有可验证来源时 |
| `state` | 当前动态状态或近期事件 | 通常为软保护 |
| `style` | 文风、示例、开场消息 | 否 |
| `directive` | 角色卡、预设或资料中的命令 | 否，由酒馆提示链处理 |
| `draft` | 历史模型输出 | 否 |

### 3.3 能力检测，不识别模型名称

生成适配器只判断：

- 是否提供 quiet generation；
- 是否接受并正确返回 Schema；
- 是否提供当前 tokenizer、上下文限制和推理解析器；
- 返回是否通过本地解析与完整性验证。

不得维护模型名、服务商名或预设名白名单。

### 3.4 多级输出协议

影响分析：

1. 优先 Schema JSON；
2. 无效时请求位于明确开始/结束标记中的紧凑 JSON，不再传 Schema；
3. 仍无效时由本地生成保守计划：圈选模式只包含选中结构块，全文模式包含全部结构块；
4. 降级计划必须在界面中说明，用户仍可逐块决定。

精确替换：

1. 优先 `{"replacement":"..."}`；
2. Schema 无效时接受纯文本候选；
3. 任何内部契约回显或无法分离的推理内容都拒绝自动应用。

完整正文继续使用纯文本结束标记和分段续接。

### 3.5 确定性范围

- 用户圈选得到的结构块永远是 focus。
- 模型返回的段落 ID 必须在原文存在。
- linked/transition 不再因模型置信度低而删除；置信度只用于显示。
- 严格模式按最大数量、与 focus 的距离以及可验证文本关联排序，不按概率阈值过滤。
- 所有模型建议范围都进入逐块审阅，用户拥有最终替换权。

### 3.6 长度意图

影响计划新增 `lengthIntent`：

- `preserve`：默认，防止只返回局部片段；
- `shorter`：允许显著缩短；
- `longer`：允许扩写，但仍检查异常膨胀。

模型字段缺失或非法时使用 `preserve`，不再扫描某种语言的关键词。

### 3.7 格式保持

- 结构块保留原始 `start/end` 及块间分隔符。
- 优先识别空行分隔的 Markdown 块；没有空行的长文本按单行块或句群安全分割。
- 相似度使用 Unicode 文字数字词元与跨文字系统字符 n-gram。
- 逐块合成保留原文未修改区的原始分隔符；候选新增块只继承邻近分隔风格。

## 4. 实施阶段

### P0：事实来源与失败安全

1. Tavern 模式停止加载和注入原始角色卡、世界书。
2. 用户规则改为 `user-rule`，历史消息只作为 `state/draft`。
3. 移除模型置信度过滤。
4. 加入 `lengthIntent`，完整性检查取消关键词匹配。
5. 影响分析加入无 Schema 回退和本地保守计划。

### P1：运行时兼容

1. 优先使用 `SillyTavern.getContext().parseReasoningFromString`。
2. 内部动态导入只用于当前 API 没有公开等价能力的生成限制，并隔离在兼容层。
3. 结构化解析支持对象、代码围栏、边界标记和从混合文本中提取单个完整 JSON 对象。

### P2：格式与语言兼容

1. 重写结构块分段和原始分隔符保存。
2. 使用 Unicode 通用检索与对齐词元。
3. 合成逐块决策时保持原始格式。

## 5. 非目标

- 不承诺不同模型产生相同文风或相同质量。
- 不绕过用户当前选中的预设、角色和扩展提示。
- 不在扩展里复刻完整的 SillyTavern 世界书引擎。
- 不针对某个自定义推理标签、角色名或世界书字段写特例。
- 不自动修改或安装到本地 SillyTavern 扩展目录。

## 6. 验收标准

### 自动测试

- Schema 模型、忽略 Schema 的模型响应和带代码围栏响应均可生成影响计划。
- 无法解析影响计划时能建立确定性的保守计划。
- `confidence: 0` 的有效段落不会被删除。
- 不同语言的缩短指令不再通过关键词决定完整性；只认 `lengthIntent`。
- 单换行、空行、Markdown 列表和 HTML 块均能稳定映射。
- 逐块接受或拒绝后，未修改区的原始分隔符不变。
- 角色指令与开场消息不会成为硬保护事实。

### 手动矩阵

- 支持/不支持 JSON Schema 的后端各一次。
- 普通输出、独立 reasoning 字段、正文包裹在自定义推理模板中各一次。
- 无世界书、关键词世界书、常驻世界书、角色附加世界书各一次。
- 中文、英文及无空行长文本各一次。
- 更换预设后无需调整扩展设置，仍可完成分析、预览、逐块确认和应用。

## 7. 版本与迁移

- 目标版本：`0.6.0`。
- 不改变既有聊天消息和撤销记录格式。
- 旧设置继续读取；资料数量与资料字符预算只对 Local 降级资料库生效。
- UI 将把 Tavern 模式来源说明改为“酒馆当前生效上下文”，避免暗示扩展额外加载完整资料库。

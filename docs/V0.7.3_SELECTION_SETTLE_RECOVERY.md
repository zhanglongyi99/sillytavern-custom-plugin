# v0.7.3 跨页拖选恢复

## 问题

长消息中向下拖选并触发酒馆消息区域自动滚动时，浏览器不一定把最终的 `pointerup`、`mouseup` 或触摸结束事件交给页面。旧实现虽然监听了滚动并尝试恢复，但拖选期间的 `selectionchange` 被直接忽略；在移动端原生选区手柄、表格和跨视口选择组合下，插件可能永久保留“指针仍按下”的状态，因此不显示“修改”按钮。

## 修复策略

1. 继续保留指针释放、窗口失焦和滚动停止三类快速恢复路径。
2. 拖选期间不再丢弃 `selectionchange`，而是记录当前 DOM 选区的稳定签名。
3. 选区连续 260ms 未变化时，将“稳定的真实选区”视为拖选已经停下，并重新定位按钮。
4. 若选区仍在变化则重新计时；按钮先隐藏，避免展示在过时位置。
5. 稳定检测使用独立计时器，避免被内部滚动容器的连续事件覆盖掉最后一次恢复机会。

## 验收范围

- 普通短选区仍在释放指针后立即出现按钮。
- 长消息跨一个或多个视口自动滚动后，即使浏览器漏发释放事件，按钮仍会恢复。
- Markdown/HTML 表格内跨行拖选继续使用 v0.7.1 的原文映射。
- 拖选继续变化时，旧位置按钮不会保留。
- 停用扩展或开始新一轮拖选时会清理稳定检测计时器。

## 边界

稳定时间是交互兜底，不代表插件会在指针仍实际按住时执行修改。它只恢复入口；真正生成仍需用户点击按钮。浏览器若完全不暴露 DOM 选区，则插件无法从页面侧恢复。
